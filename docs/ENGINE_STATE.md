# Состояние движка Gold Client (`ref_params_t`) и cvar-переменные

Как движок публикует «что происходит в кадре»: позиция и углы камеры, время,
`onground`, уровень воды, здоровье, размер окна. Всё это нужно любому коду,
который считает направление взгляда, положение скелета на экране или состояние
движения игрока.

Смещения записаны в `crates/golden-sdk/src/offsets.rs` (`ref_params`,
`hw::IN_GAME`, `client::cvars`, `client::view`), читаются через
`golden_sdk::state::EngineState` и `golden_std::State`.

## Откуда взялась структура

`FUN_100B4700` (`hw.dll`) каждый кадр копирует `0x3A` двойных слов из
`0x12F9C5A8` в `0x1043E25C`:

```c
puVar3 = &DAT_12f9c5a8;
puVar5 = &DAT_1043e25c;
for (iVar1 = 0x3a; iVar1 != 0; iVar1 = iVar1 + -1) {
  *puVar5 = *puVar3;
  puVar3 = puVar3 + 1;
  puVar5 = puVar5 + 1;
}
```

То есть в `.data` `hw.dll` лежит **копия** клиентского `ref_params_t`, и движок
берёт камеру, время и флаги именно из неё. Это удобнее, чем ловить структуру
в стеке: адрес постоянный, а значения обновляются до отрисовки.

Единственная ссылка на весь блок в статическом образе — запись
`FUN_100B4700:100b485d -> 1043e260`, поэтому найти его «по ссылкам» не
получается; искали по копирующему циклу.

## Раскладка

База — `0x1043E25C` (`hw.dll + 0x43E25C`). ✔ — сверено живым замером,
← — позиция выведена из порядка полей и пока не наблюдалась в отдельном
состоянии.

| Смещение | Поле | Тип | Что это |
| --- | --- | --- | --- |
| `+0x00` | `vieworg` | `vec3` ✔ | позиция камеры |
| `+0x0C` | `viewangles` | `vec3` ✔ | углы камеры с отдачей |
| `+0x18` | `forward` | `vec3` ✔ | единичный вектор взгляда |

| `+0x30` | `up` | `vec3` ✔ | единичный вектор вверх |
| `+0x3C` | `frametime` | `float` ✔ | длительность кадра, `0.0243` |
| `+0x40` | `time` | `float` ✔ | игровое время в секундах |
| `+0x44` | `intermission` | `int` ← | идёт смена карты |

### Чем это подтверждено

* `vieworg − simorg = (0.03, 0.03, 17.03)`, а `view_ofs = (0, 0, 17)` — то есть
  `vieworg = simorg + view_ofs`, как и должно быть.
* `cl_viewangles` совпали с `viewangles` до третьего знака в замере без стрельбы
  (отдачи не было).
* `width/height = 1920×1080` — фактический размер окна.
* `health = 100`, `viewsize = 120`, `maxclients = 32`, `viewentity = 1` —
  значения совпадают с тем, что было в игре.
* `onground` переключался `1 → 0` при прыжках, `waterlevel` держался `0` на суше.

## Сверка со смещениями из `better-fastmath`

| Имя там | Адрес | Что это на самом деле |
| --- | --- | --- |
| `LOCAL_VIEW` | `hw + 0x288040` | `ref_params.viewangles` ✔ (те же значения) |
| `LOCAL_VIEW_CLEAN` | `hw + 0x43E2DC` | `ref_params.cl_viewangles` ✔ (углы без отдачи) |
| `GLOBAL_TICK` | `hw + 0x43E29C` | **не тик**, а `ref_params.time` — `float` секунды (`1855.1`); тика здесь нет |
| `ON_GROUND` | `hw + 0x43E2AC` | `ref_params.onground` ✔ |
| `IN_GAME` | `hw + 0x274B18` | флаг «карта загружена» ✔ |
| `IN_MENU` | `hw + 0x333A62C` | флаг меню ✔ |
| `CHAT_OPENED` | `hw + 0x27E2E00` | флаг открытого чата ✔ |
| `M_YAW` | `client + 0x1B1164` | указатель на `cvar_t "m_yaw"`, значение `+0xC` = `0.022` ✔ |
| `SENS` | `client + 0x1B1174` | указатель на `cvar_t "sensitivity"`, значение `2.5` ✔ |
| `DEFAULT_FOV` | `client + 0x228AB8` | **не `cvar_t`**, а строка `"default_fov"` рядом с ним ✔ |
| `FOV_1..3` | `client + 0x1CE4D0`, `0x1F4ACC`, `0x224A34` | все три читались как `int 90`; какой из них `m_iFov` — не определено |

`cvar_t` в этой сборке: `+0x00` — `char *name`, `+0x08` — `int flags`,
`+0x0C` — `float value`.

## Производные признаки

* **Присед** — `view_ofs.z < 16.5` (стоя `17`, в приседе движок опускает глаза).
  Флага приседа в `ref_params` нет.
* **Лестница** — отдельного флага в `ref_params` тоже нет: `movetype` живёт в
  серверном состоянии сущности. Пока используется эвристика
  `!onground && !in_water && |simvel.z| > 1`; точный признак появится вместе с
  `entity_state.movetype` в SDK.
* **Горизонтальный FOV** — движок задаёт `m_iFov` по соглашению 4:3 и расширяет
  по аспекту окна: `tan(fov_y/2) = tan(fov_x/2) * 3/4`,
  `fov_x' = 2·atan(tan(fov_y/2) · width/height)`. Для 1920×1080 из `90`
  получается `106.26°`. Реализация — `golden_sdk::state::horizontal_fov`.

## Как перепроверить после обновления игры

`golden_sdk::validate::run()` — семь проверок по этому блоку:

1. `vieworg = simorg + view_ofs` (ловит сдвиг `+0x00`/`+0x64`/`+0x70`);
2. размер окна `>= 320×240` (ловит `+0xD8`);
3. `maxclients` в `1..=64` (ловит `+0xAC`);
4. `viewentity` в диапазоне сущностей (ловит `+0xB0`);
5. `waterlevel` в `0..=3` (ловит `+0x54`);
6. три кандидата `m_iFov` равны между собой и в `10..=180`;
7. `cvar_name(M_YAW) == "m_yaw"` и `cvar_name(SENSITIVITY) == "sensitivity"` —
   проверка идёт по строке имени, а не по значению, поэтому переживает смену
   настроек пользователем.
