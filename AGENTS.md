# golden-client SDK

SDK на Rust для модов под [Gold Client](https://goldclient.ru) — клиент Counter-Strike 1.6.
Всё, что нужно моду: доступ к движку (`hw.dll`) и клиенту (`client.dll`), сущности,
studio-модели, хуки, отрисовка поверх кадра, консольные команды, ввод, корректная
выгрузка DLL без перезапуска игры.

## Что читать первым

1. `README.md` — устройство крейтов и быстрый старт.
2. `docs/STUDIO_REVERSE.md` — разбор studio-пути Gold Client: таблица
   `engine_studio_api_t`, объект `CStudioModelRenderer`, его vtable, адреса.
3. `crates/golden-sdk/src/offsets.rs` — все смещения движка в одном месте.

## Раскладка

| Путь | Что там |
|---|---|
| `crates/golden-sdk` | `no_std` + `alloc`. Адреса и смещения, память, сущности, разбор `.mdl`, интерфейс studio-рендерера, OpenGL, `retour`-детуры, консоль, лог, Win32 напрямую. |
| `crates/golden-std` | Слой поверх SDK: `esp`, `Overlay`, позы, реестр хуков, реестр команд, ввод, планировщик по кадрам, `unload`, запуск игры с ботами. |
| `examples/` | Тонкие моды: `esp`, `auto-bhop`, `model-viewer`, `diagnostics`. |
| `tools/inject` | Загрузка DLL в живой `hl.exe`. |
| `tools/stand` | Запуск игры с ботами, инъекция, счётчики из лога. |
| `docs/` | Разбор движка. |

SDK не тянет `std` намеренно: системное сделано прямыми вызовами Win32. Если
нужен `std` — это `golden-std`, а не SDK.

## Сборка и тесты

Игра 32-битная, поэтому только цель `i686-pc-windows-msvc`:

```powershell
rustup target add i686-pc-windows-msvc
cargo build --workspace --release --target i686-pc-windows-msvc
cargo test --workspace
```

DLL примеров — в `target/i686-pc-windows-msvc/release/`. Если DLL занята живым
процессом, собирайте с `--target-dir` во временный каталог.

## Проверка в живой игре

1. **Перезапустите игру перед инъекцией.** `hl.exe` однопроцессный, а уже
   загруженную DLL нельзя заменить на живом процессе: старая копия останется
   в памяти и будет дублировать отрисовку. Проверять надо ту сборку, которую
   только что собрали.
2. Инъекция: `golden-inject.exe <pid hl.exe> <путь к dll>`.
3. Лог и файл команд лежат рядом с DLL: `golden-client.log`, `golden-commands.txt`.
4. Управление извне — строки в `golden-commands.txt` исполняются как команды
   консоли (так стенд замораживает ботов и снимает кадр). Строки, которые были
   в файле до загрузки мода, не исполняются: остатки прошлых прогонов не должны
   отключать мод на старте.
5. Кадр для проверки: снять экран с клиентской области окна игры. Свёрнутое
   окно не рисует, поэтому сначала развернуть.
6. Выгрузка: команда `unload_esp` в консоли снимает хуки, ввод и команды и
   **останавливает мод, но не освобождает DLL** — образ остаётся в памяти
   процесса. Проверено дампом (`hw.dll+0xBD793`, `mov esi,[ecx+edx*4]` с нулевой
   базой): после `FreeLibraryAndExitThread` движок прыгает в освобождённую
   таблицу интерфейса, и игра падает — причём не сразу, а на следующем заходе в
   интерфейс, поэтому короткая проверка «жива» ничего не доказывает. Снять мод
   и реально освободить образ (нужно для пересборки DLL, риск падения) —
   `!free` в `golden-commands.txt`.
7. **Если мод уже загружен, пересборка невозможна: файл DLL занят процессом.**
   Либо закрыть игру, либо собрать в другую папку и инжектить копию:
   `cargo build --release --target i686-pc-windows-msvc --target-dir target\check`,
   затем скопировать DLL под новым именем и инжектить её. Ещё вариант — `!free`
   (см. выше), но он может уронить игру.
8. **Несколько модов сразу: порядок важен.** Моды опознаются по экспорту-метке
   `golden_client_mod` (имя файла и каталог роли не играют,
   `golden_sdk::module::other_mods()`). Загруженный последним стоит в цепочке
   `g_pStudioInterface` верхним и вызывает нижнего как `previous`. Выгружать
   надо сверху вниз: выгрузка нижнего, пока верхний жив, отменяется
   (`golden_std::unload::can_unload`) с записью в лог, потому что у верхнего в
   цепочке остался бы указатель в освобождённый мод.

Стенд заменяет ручную возню с меню:

```powershell
golden-stand.exe run example_esp.dll --map de_dust2 --bots 3 --seconds 120 `
    --needle "esp: моделей" --keep
```

## Жёсткие правила

* **Перехваты ставим из рендер-потока**, в первом вызове `StudioDrawPlayer`, а не
  из стартового потока: править байты функции, которую движок исполняет из
  другого потока, нельзя — игра падает.
* **Интерфейс рендерера подменяем только через `hooks::interface`.** Он патчит
  слоты таблицы клиента и восстанавливает их. Менять `g_pStudioInterface`
  (`hw+0x271B04`) нельзя: движок держит указатель в кэше и после выгрузки прыгает
  в освобождённую память.
* **Аксессор оригинала из `hook!` работает только для хуков, поставленных через
  `hooks::install`.** Для подмены интерфейса оригинала в реестре нет, поэтому
  оригинал зовём по указателю из своего статика (иначе паника в FFI).
* **Команды снимаем до хуков, свою команду — не изнутри её же колбэка**: движок
  вернётся в освобождённую память. В `golden_std::unload` порядок уже правильный,
  не ломайте его.
* **Перед `FreeLibrary`** ждём, пока счётчик «мы внутри своего кода» станет нулём,
  и останавливаем свои потоки. Трамплин не освобождаем, пока в хуке может быть
  поток.
* **В репозиторий не попадают** игровые файлы, извлечённые ассеты и
  декомпилированный код: только исходники SDK.

## Грабли движка (проверено в игре)

| Что | Как есть на самом деле |
|---|---|
| Номер слота игрока | `cl_entity_t + 0x00` (`entity::INDEX`). `+0x04` — `modelindex`, у всех игроков равен 1. |
| Команда игрока | `g_PlayerExtraInfo`, заполняется сообщением `TeamInfo`. По имени модели определять нельзя: скины кастомные. |
| `glColor4f` на линиях | Движок оставляет `GL_LIGHTING`, цвет вымывается в белый. В скоупе рисования выключаем `GL_LIGHTING`/`GL_COLOR_MATERIAL`, ambient `(1,1,1,1)`. |
| Текст не виден | Движок держит включённым клиентский массив цветов. Выключаем `GL_COLOR_ARRAY`, `GL_VERTEX_ARRAY`, `GL_TEXTURE_COORD_ARRAY`. |
| Видимость сквозь стены | `glDisable(GL_DEPTH_TEST)` бесполезен: движок включает проверку глубины внутри своего рендера. Нужен `glDepthFunc(GL_ALWAYS)`, а надёжнее — рисовать в конце 3D-сцены. Видимую часть контура красят вторым проходом с `GL_LEQUAL`, а в первом (`GL_ALWAYS`) выключают запись глубины `glDepthMask(0)`, иначе контур сравнивается сам с собой. |
| Белые модели и тёмная карта после своей отрисовки | Движок сам текстуры и освещение не включает — считает, что состояние уже правильное. Поэтому после своего прохода: `glEnable(GL_TEXTURE_2D)` (иначе оружие в руках рисуется без текстуры), `glDisable(GL_LIGHTING)` (иначе мир после нас тёмный). `glPopAttrib` с `GL_TEXTURE_BIT` тоже нельзя: кэш привязанной текстуры у движка свой, и откат привязки ломает следующую модель. Сохраняем `GL_ENABLE_BIT`, `GL_DEPTH_BUFFER_BIT`, `GL_COLOR_BUFFER_BIT`, `GL_POLYGON_BIT`, `GL_LINE_BIT`, `GL_CURRENT_BIT`. |
| Контейнеры и ящики | Это brush-модели, движок рисует их после игроков, поэтому контур под ними пропадает. Отсюда перехват `HUD_DrawNormalTriangles` (`client.dll + 0xB16D0`). |
| Перерисовка модели в конце кадра | `StudioDrawPlayer` вернёт 0 полигонов, пока не выставлена «текущая сущность» (`hw+0x78E470`). |
| Смена буферов | Экспорт называется `wglSwapBuffers`, а не `SwapBuffers`; `opengl32.dll` грузится позже мода, поэтому поиск надо повторять. |
| Консоль | История консоли Gold Client — UTF-16 в куче, приёмник строк в `GameUI.dll`. `Con_Printf` в `hw.dll` (`0x1010FAB0`) её не печатает, фильтр там бесполезен. |
| `MODULEINFO` | `SizeOfImage` по смещению 4, а не 12. Перечисление модулей `hl.exe` из PowerShell под WOW64 врёт — проверяйте иначе. |
| Дампы крашей | `C:\Games\CS 1.6 GoldClient\crashdumps`. Поле «Exception at address» в `crash.log` — артефакт сканирования стека, настоящий адрес только в `.dmp`. |

## Стиль

* Комментарии и документация — по-русски, код и идентификаторы — по-английски.
* В `golden-std` один модуль на возможность (`esp`, `render`, `hooks`, `concommand`,
  `input`, `scheduler`, `unload`). Примеры остаются тонкими: настройки, а не механика.
* Перехваты объявляются макросом `golden_std::hook!`; установка — через
  `hooks::install`, чтобы реестр знал о хуке и снял его при выгрузке.

## Скиллы

В `skills/` лежат рабочие инструкции для агента:

* `skills/reverse-engineering/SKILL.md` — Ghidra/IDA, IL2CPP, живая память, форматы
  файлов. Нужен, когда надо разобрать функцию `hw.dll`/`client.dll`.
* `skills/game-automation/SKILL.md` — запуск игры, скриншоты, ввод, чтение логов.
  Нужен для проверки мода в реальной игре.
* `skills/mod-any-game/SKILL.md` — общий цикл моддинга и правила безопасности.

Читайте `SKILL.md` перед соответствующей работой; вложенные файлы скилла — по
ссылкам из него.

`mod-any-game` взят из [universal-modder](https://github.com/rehan-remade/universal-modder).
Упоминаемые в нём `um` и `knowledge/` — внешний инструмент и внешняя база знаний,
в этом репозитории их нет.
